# AI 每日学习站 — 设计规格

**日期：** 2026-09-22  
**状态：** 已确认；实现计划见 `docs/superpowers/plans/2026-09-22-ai-daily-learn.md`  
**产品形态：** 网页优先，预留日后微信小程序复用同一内容源

## 1. 背景与目标

面向完全零基础的个人学习者，提供每天约 40 分钟的 AI 学习节奏：

- **早上 7:30**：约 20 分钟「AI 基础」阅读 + 小测  
- **下午 17:30**：约 20 分钟「当日 AI 热点」阅读 + 小测  

以自己使用为主，可通过链接分享给朋友。内容全自动生成与发布，用户几乎不运营。

### 成功标准

- 每天两更按时可读；失败时有降级，不出现空白首页  
- 单篇约 20 分钟阅读量（约 1500～2500 字）+ 2～3 道选择题  
- 打开即知「现在该学哪一更」；分享链接无需登录即可阅读同一篇  
- 第一版可在一周内做出可日常使用的最小可用产品（MVP）

### 明确不做（第一版）

- 用户账号 / 登录  
- 推送通知（邮件、微信、App 推送）  
- 付费、评论、社区  
- 复杂错题本与长期进度画像  
- 微信小程序（仅预留内容接口，不在本期实现）

## 2. 用户与场景

| 角色 | 场景 |
|------|------|
| 主用户（自己） | 早/晚打开网页，按推荐入口读完一更并做小测 |
| 朋友 | 点开分享链接，只读该篇，无需注册 |

时区固定为 **Asia/Shanghai**。更新时刻：

- 基础课：每天 **07:30**  
- 热点：每天 **17:30**

## 3. 产品体验

### 3.1 首页

首页只回答一件事：**现在该学哪一更**。

- 07:30 之后：主 CTA 为「今日基础」；「今日热点」为次要入口（若已更新）或「预计 17:30 更新」  
- 17:30 之后：主 CTA 为「今日热点」；「今日基础」为次要入口（补看/复习）  
- 未到当日首次更新：展示下一更预计时间，可提供「复习昨日」入口  
- 可选展示最近若干天的历史入口（按日期列表）

### 3.2 单篇内容结构（基础 / 热点共用骨架）

1. 标题 + 预计阅读时间  
2. 开篇（约 3～5 分钟）：今天学什么 / 为什么重要  
3. 正文 3～4 小节  
   - **基础**：概念白话讲解 + 生活类比  
   - **热点**：发生了什么 → 为什么火 → 和普通人有什么关系  
4. 文末 2～3 道选择题；即时对错反馈；不持久化成绩（无账号）  
5. 「一句话带走」总结  
6. 热点文固定免责声明：根据公开信息整理，非投资/内幕建议  

### 3.3 分享

每更独立 URL，示例：

- `/learn/2026-09-22/morning` — 当日基础  
- `/learn/2026-09-22/afternoon` — 当日热点  

朋友打开即为同一只读内容，无登录墙。

## 4. 内容体系

### 4.1 早间基础课

- 维护一份 **AI 小白入门大纲**（约 60～90 天，一天一个小主题）  
- 主题示例方向：模型是什么、提示词、幻觉、Token、训练与推理、常见工具分类等  
- 按 **自站点上线日（或配置的 `curriculumStartDate`）起算的 Day N** 映射大纲；断更不跳天：某日生成失败则该 Day 延后到下次成功早更（大纲进度与日历解耦，避免缺课）  
- 生成要求：零基础口吻；必要术语必须跟一句人话解释；可轻量衔接「昨天提到的 X」  
- 篇幅：1500～2500 字量级，对应约 20 分钟  

### 4.2 晚间热点

1. 从公开 AI/科技资讯源拉取当日候选（RSS 或等价公开列表）  
2. 模型选出 **1 个主热点**，可选 **1～2 条短讯**  
3. 写成上述热点结构 + 小测 + 一句话带走  

**降级策略（必须）：**

- 资讯过少或源失败 → 「经典热点复盘」或「工具打卡」稿，仍保证约 20 分钟可读  
- 生成失败 → 首页提示延迟，并提供昨日内容；不展示空白正文区  

### 4.3 生成质量闸门

自动校验（不依赖人工审稿）：

- 字数落在目标区间；过短/过长则重试一次  
- 仍不合格 → 若该槽位尚无成功稿，则写入并标记 `draft_quality`，首页提示「今日稿件质量降级，仍可阅读」；若已有成功稿则不覆盖  
- 禁止纯术语堆砌（通过提示词约束 + 简单启发式检查，如术语密度告警）

## 5. 系统架构

三块积木：

```
定时生成器  --写入-->  内容库  <--读取--  学习网页
     |                    |
  大纲 / RSS            按日期+时段的结构化文章
  + LLM API
```

| 组件 | 职责 |
|------|------|
| 学习网页 | 首页推荐、文章页、小测交互、历史与分享路由 |
| 内容库 | 存储每日 `morning` / `afternoon` 结构化数据（标题、小节、测验、元数据） |
| 定时生成器 | 07:30 / 17:30（Asia/Shanghai）触发：取材 → 写稿 → 校验 → 入库 |

### 5.1 技术选型（MVP）

- **前端/全栈：** Next.js（App Router），便于后续小程序只换壳、复用内容 API  
- **内容存储：** 优先 JSON 文件或轻量 DB（如 SQLite / 托管 KV）；以「按日期可分享、可备份」为准  
- **定时：** 托管平台 Cron（如 Vercel Cron）或等价调度；本地开发可用手动脚本触发  
- **生成：** 大模型 API 写稿；密钥仅存在服务端/CI 环境变量，永不下发到浏览器  

### 5.2 核心数据模型（逻辑）

```text
Lesson {
  date: "YYYY-MM-DD"
  slot: "morning" | "afternoon"
  type: "basics" | "hotspot" | "fallback_classic" | "fallback_tool"
  title: string
  estimatedMinutes: number
  intro: string
  sections: [{ heading, body }]
  quiz: [{ question, options[], answerIndex, explanation }]
  takeaway: string
  disclaimer?: string          // 热点必填
  status: "ok" | "draft_quality" | "failed_placeholder"
  sources?: [{ title, url }]   // 热点可选
  createdAt: ISO datetime
}
```

### 5.3 内容 API（供网页与未来小程序）

- `GET /api/today` — 根据当前上海时间返回推荐槽位与可用文章摘要  
- `GET /api/lesson/:date/:slot` — 单篇全文  
- `GET /api/history?limit=n` — 最近日期列表  

第一版小测仅前端判分，不写回服务器。

## 6. 错误处理与可靠性

| 情况 | 行为 |
|------|------|
| LLM 调用失败 | 重试有限次数；仍失败则不覆盖已有成功稿；首页提示延迟 + 链到昨日 |
| 热点源全部失败 | 走 fallback 类型稿并入库 |
| 校验失败 | 重试生成一次；再失败：无成功稿则入库 `draft_quality`，有成功稿则不覆盖 |
| Cron 未触发 | 提供手动「补跑今日某槽位」的管理脚本（仅本地/持有密钥者可跑） |

## 7. 测试要点

- 时间边界：06:59 / 07:30 / 17:29 / 17:30 / 跨日 00:00 的首页推荐是否正确  
- 分享链接：无 cookie 下可打开 `/learn/:date/:slot`  
- 生成器：大纲第 N 天映射正确；热点空源走降级；失败不破坏昨日内容  
- 小测：选对/选错反馈与解析展示正确  
- 移动端可读：单栏排版，正文舒适字号与行距  

## 8. 里程碑（实现阶段预览）

1. 静态壳 + 假数据跑通首页与文章/小测/分享路由  
2. 大纲文件 + 早间生成脚本入库  
3. 热点拉取 + 晚间生成 + 降级  
4. Cron 接入上海时区两档时刻  
5. 部署上线 + 环境变量说明（给零基础的操作清单）  

## 9. 开放决定（已拍板）

| 项 | 决定 |
|----|------|
| 载体 | 网页优先，小程序以后再说 |
| 内容 | 全自动 |

| 架构 | 轻量网页 + 定时生成 + 内容库 |
